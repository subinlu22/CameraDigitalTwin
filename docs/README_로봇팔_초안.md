# SO-101 로봇팔 학습 시뮬레이터 — README 초안

> 초안 (11/16 밤). 데모 영상·스크린샷·확인 안 된 기능은 ⏳ 표시. 마무리 때 루트 README에 합치거나 따로 둠.

## 개요

학교에 로봇팔(SO-ARM101)은 한 대뿐이고 배우려는 학생은 여럿이라, **실물과 똑같이 움직이는 디지털 로봇팔**을 Unity로 만들었습니다.

- **연습 모드**: 로봇 없이 Unity 안에서 관절 조작, 자세 저장·재생, 벨트 위 뚜껑 집기를 연습
- **실물 모드**: 같은 동작을 실제 로봇팔(흰 팔)이 따라 함 — 모든 명령은 안전 범위·속도 제한을 거침
- 기존 컨베이어 검사 디지털트윈(카메라 판정 → Unity 벨트 위 뚜껑 재현) 위에 얹은 프로젝트

## 할 수 있는 것

| 기능 | 상태 |

| 저장한 자세를 순서대로 재생 (자세마다 1초 머묾) | ✅ (실물 재생 ⏳) |

| 가벼운 연습 룩 ↔ 데모 룩 전환(F5), FPS 표시(F4) | ⏳ 코드만 |

## 환경

| 구분 | 내용 |
|---|---|

## 시스템 구조

```
[리더 팔] ─USB─▶ leader_hub ─UDP 5060─▶ Unity (LeaderArmReceiver) ── 미러링
                                     │
                              Unity 팔 6관절 목표 각도
                              (RobotJointTester: 초당 10° 제한)
                                     │
                 UnityTargetSender ─UDP 5063─▶ [컨트롤 패널 브리지] ─USB─▶ [흰 팔]
                 UnityToFollowerGUI ─UDP 5061(명령) / 5062(상태)─┘
                                       안전 범위 자르기 · 속도 제한 · 0.3초 끊김 정지 · 벨트 충돌 검사
```

| 스크립트 | 역할 |
|---|---|
| `UnityToFollowerGUI` | 모드 전환 (리더 / 연습 / 실물 / 로봇 없이 연습), 브리지 명령·상태 |
| `RobotJointTester` | 관절 목표 각도를 초당 maxSpeedDps로 천천히 넣음 |
| `ArmPoseMover` | 벨트를 피하는 경유 자세 계산 (SafePath) |
| `PoseLibrary` | 자세·그룹·녹화 동작 저장 (`StreamingAssets/so101_poses.json`), 순서대로 재생, 동작 재생 |
| `PracticeLid` | 연습용 뚜껑을 두 손가락 사이 아래 면에 놓음 |
| `LookQualitySwitch` | 가벼운 연습 룩 ↔ 데모 룩, FPS 측정 |
| `GripperGrab` | 두 손가락이 닿고 더 쥐면 잡고, 벌리면 놓음 |
| `TwinSidePanel` (+ `.Poses`) | 오른쪽 패널: 관절 표·수동 제어 / [자세] 탭 |
| `Tools/so101_bridge` | Python 컨트롤 패널 — 흰 팔에 쓰는 유일한 길, 안전 규칙 담당 |

## 안전 설계

| 결정 | 이유 |
|---|---|
| 흰 팔에 쓰는 건 브리지 하나뿐 | 안전 범위·속도·끊김 정지를 한곳에서 확인 (`docs/so101_safety.md`) |
| [흰 팔 실제로 움직이기]는 두 번 눌러야 시작, 6관절 차이 2° 안일 때만 | 켜는 순간 튀는 것 방지 |
| Unity 쪽도 초당 10° 제한 | 슬라이더를 확 끌어도 흰 팔은 천천히 |
| 크게 움직일 땐 위로 든 뒤 옮김 | 한꺼번에 움직이면 집게가 벨트·뚜껑을 밀었음 |
| 로봇 없이 연습 모드는 브리지로 아무것도 안 보냄 | 연결이 나중에 생겨도 흰 팔이 갑자기 안 움직이게 |
| 집게는 "보낸 명령 각도"로 저장 | 막혀서 멈춘 실제 각도로 재생하면 힘이 안 들어가 놓침 |

## 트러블슈팅

| 문제 | 원인 | 해결 |
|---|---|---|
| 유니티 조종을 켜는 순간 팔이 ㄱ자로 튐 | 슬라이더 기본값 0° | 켤 때 지금 목표 각도를 슬라이더에 먼저 넣음 |
| 6관절을 한꺼번에 옮기면 집게가 벨트를 밂 | 관절마다 도착 시간이 달라 중간 자세가 낮아짐 | 위로 들기 → 어깨 회전 → 내려가기 (SafePath) |
| 쉬는 자세에서 나올 때 벨트에 닿음 | 접힌 팔이 벨트 쪽으로 펴짐 | 어깨 +45° 먼저, 팔 먼저 펴고 손목 |
| 재생한 집게가 뚜껑을 놓침 | 실제 각도(막힌 각도)로 재생 → 서보 힘이 거의 0 | 집게는 명령 각도로 저장 |
| 룩·재질 숫자를 아무리 바꿔도 실사처럼 안 나옴 (물체가 떠 보임, 하얗게 뜨거나 칙칙함) | Built-in 렌더 파이프라인 한계: 실시간 간접광·접촉 그림자가 없음 + 데모 장면의 원래 조명 20여 개·작업대 반사판·원래 후처리가 프리셋 위에 겹침 | 같은 모델을 HDRP로 찍어 비교 (Built-in / HDRP 실시간 / HDRP 경로 추적) → 경로 추적에서 바로 원하는 질감. 시뮬레이터(실시간)는 Built-in 라이트 버전, 사진·영상은 HDRP 고퀄 버전으로 나눔 |
| HDRP 복사본에서 찍을 때 자꾸 멈추고 꺼짐 | 유니티 두 개 동시 실행(뒤 창은 거의 멈춤, MCP가 같은 이름이라 복사본 구분 못 함) + 경로 추적 1024번 누적에서 그래픽카드 시간 초과 | 찍을 땐 원본 유니티를 끄고 복사본 창을 앞에 둠, 누적은 256~384번 |
| 손가락 사이에 뚜껑이 안 들어감 | 볼록 충돌 모양이 손가락 사이를 막음 | 손가락 크기 얇은 상자(FingerBox)로 바꿈 |

## 실행 방법

1. Unity 6000.3.11f1로 프로젝트 열기 → `SampleScene` → Play
2. **로봇 없이**: 오른쪽 패널 로봇 카드 → [로봇 없이 연습] → [자세] 탭에서 그룹 고르고 [▶ 순서대로 재생]
3. **실물**: `Tools/so101_bridge/panel_start.bat` → [두 팔 연결] → Unity [유니티로 조종] → 차이 2° 안이면 [흰 팔 움직이기] 두 번
4. 녹화: [● 녹화] → 팔 움직이기 → [■ 멈춤] → [▶ 동작 재생 ½]
