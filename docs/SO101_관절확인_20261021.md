## 2. 유니티 ArticulationBody (Unity MCP로 읽음)

| 조인트 | Joint Type | 회전축 (로컬 / 월드) | Lower / Upper (°) | 현재 값 (Edit 모드) |
|---|---|---|---|---|
| shoulder_pan | Revolute, Twist Limited | -Y / +Y (수직) | -110 / 110 | 0 |
| shoulder_lift | Revolute, Twist Limited | -Y / -X | -100 / 100 | 0 |
| elbow_flex | Revolute, Twist Limited | -Y / -X | -96.83 / 96.83 | 0 |
| wrist_flex | Revolute, Twist Limited | -Y / -X | -95 / 95 | 0 |
| wrist_roll | Revolute, Twist Limited | -Y / -Z (아랫팔 방향) | -157.21 / 162.79 | 0 |
| gripper | Revolute, Twist Limited | -Y / ≈+X | -10 / 100 | 0 |

- anchorRotation은 6개 모두 `(0, 0, -0.7071, 0.7071)` → 회전축 = 링크 로컬 -Y
- xDrive: target 0, stiffness 0, damping 0, forceLimit 10 (6개 모두). 이대로는 target을 줘도 따라가지 않음
- Swing Y/Z는 Free로 저장돼 있음 (Revolute에서 동작에 영향이 있는지는 확인 못 함)
- 어깨 들기·팔꿈치·손목 굽힘의 축이 서로 평행 (월드 -X)
- Play 모드의 jointPosition 값은 확인 못 함

## 4. 0자세 비교

**유니티 (모든 관절 0°)** — 옆에서 보면 "ㄱ"자
- 윗팔(upper_arm → lower_arm) 76°로 거의 수직
- 아랫팔(lower_arm → wrist) 2.2°로 거의 수평
- 손목 → 그리퍼 0°, 로봇 정면(로봇 기준 +Z, 월드 -Z)을 향함

**실물 (리더암을 손으로 ㄱ자로 맞춤)** — 웹 시뮬레이터 리더 표

| 조인트 | 틱 | 시뮬레이터 각도 | 판단 |
|---|---|---|---|
| 어깨 회전 | 2135 | -1.8° | 일치 |
| 어깨 들기 | 3182 | -2.9° | 일치 |
| 팔꿈치 | 1568 | 10.3° | +10° — 손으로 맞춘 오차인지 확인 못 함 |
| 손목 굽힘 | 1137 | -7.0° | -7° — 손으로 맞춘 오차인지 확인 못 함 |
| 손목 회전 | 2170 | -1.1° | 일치 |
| 그리퍼 | 2282 | 21.4° | 집게가 조금 벌어진 상태 |

- 반전 칸: 6개 모두 체크 안 함
- 시뮬레이터 3D 팔도 ㄱ자로 보임
- 팔로워암은 리더암을 0.6° 이내로 따라감 (팔로워 표: 실제/지시 차이 0.0~0.6°)

## 5. 다음 단계(10/22)에 쓸 보정값 제안

- 시뮬레이터가 이미 틱을 URDF 기준 각도로 바꿔주므로, **그 각도를 그대로 유니티에 보낸다** → 오프셋 0
- 방향은 6개 모두 +1로 시작.
  유니티 URDF Importer가 좌표계를 바꾸면서 +/−가 뒤집혔을 수 있으므로(확인 못 함),
  관절 하나씩 움직여 시뮬레이터 3D 팔과 같은 쪽으로 도는지 보고 반대면 −1로 바꾼다
- 처음엔 리더암 각도를 사용. 실제 로봇 위치를 정확히 보여줘야 하면 팔로워암 값으로 바꾼다
